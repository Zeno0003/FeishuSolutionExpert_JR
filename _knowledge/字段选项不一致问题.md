# 字段选项不一致导致 1254302 问题

## 现象

配件拆分时，某些记录写入 `采购收货表` 报 `1254302 Permission denied`，其他记录正常。

## 根因

来源表 `辅助填表_采购收货(芳)` 与目标表 `采购收货表` 的同名字段选项不完全一致。当来源值为目标表不存在的选项时，飞书 API 校验失败。

## 字段选项差异 (2026-05-23)

| 字段 | 类型 | 来源表独有 | 目标表独有 |
|------|------|-----------|-----------|
| 供应商名称 | MultiSelect | 蔡雨诗 | 婷婷, 小北, 玩机数码 |
| 商品型号 | SingleSelect | - | rmbuds6pro, mismartband10 等 19 个 |
| 颜色 | SingleSelect | - | freearc, freeclip2 等 18 个 |
| 成色 | SingleSelect | R, ZT, E | - |

完整对比可用 `server/_compare_fields.ts` 脚本查看。

## 触发链路

1. 来源表字段（MultiSelect type:4）API 返回数组 `["蔡雨诗"]`
2. `split.ts` 将数组原样写入目标表同名字段
3. 飞书校验目标表无"蔡雨诗"选项 → `1254302`

## 当前方案：跳过 + 告警（已实现 2026-05-24）

**拆分前拉取目标表字段选项做校验，不匹配的字段值跳过不写，拆分继续。**

### 实现概览

- `server/src/utils/fieldSync.ts` — `buildFieldGuard()` 拉取目标表选项列表，`validateFields()` 过滤不合法值
- `server/src/commands/split.ts` — 拆分时先校验再写入，跳过的字段及原值记入 errors 告警

### 效果

- 无 1254302 错误，拆分正常完成
- 跳过的字段会在输出中明确列出，便于事后手动补数据

### 已知局限

- 尝试过 API 自动同步方案（`appTableField.update`），但飞书国内版缺少 `base:field:update` 权限范围，API 报 1254302
- 当前方案的副作用：不匹配字段留空，需人工后续处理
- 若飞书后续开放字段更新权限，可重新启用自动同步
