# 06 — 配件拆分脚本方案：解决并发乱序

> 产出日期：2026-05-22 | 状态：v1 初稿

## 背景

用户在「辅助表格」中输入一条整机收货记录，通过飞书自动化在「收货表」自动生成 3 条配件记录（L 左耳机 / R 右耳机 / C 充电仓）。当前触发条件是"自动生成"单选字段。当用户像 Excel 那样拖拽填充多行时，飞书自动化并发执行，导致生成顺序错乱 —— 不是逐行完成 L→R→C 再处理下一行，而是各行交叉执行。

**问题本质**：飞书原生自动化的触发是异步并发的。N 条记录同时触发 = N 个自动化实例并发运行，彼此不等待。

**脚本为什么能解决**：JavaScript 是单线程同步执行的。一个脚本实例内，`for` 循环按顺序处理每条整机记录，每条记录内部 `await` 依次创建 L→R→C，完整走完一条再走下一条。不存在交叉。

## 方案概要

### 整体思路

1. 辅助表格中保留「自动生成」复选框（作为"待处理"标记），但不用于触发自动化
2. 新建一个「操作面板」子表，放一个**按钮**：**「一键拆分配件」**
3. 按钮触发自动化 → 执行脚本 → 脚本遍历所有「自动生成=是 且 已拆分≠是」的记录 → 按顺序逐条生成 L/R/C

### 表结构调整

#### 辅助表格（整机收货）

| 字段 | 类型 | 作用 |
|------|------|------|
| 自动生成 | 复选框 | 用户勾选表示"这条需要拆分"（仅标记，不触发自动化）|
| 已拆分 | 复选框 | 脚本处理完后自动勾选，防止重复拆分 |
| 整机编号 | 自动编号/文本 | 用于关联配件记录，区分归属 |
| …其他字段… | — | 型号、颜色、数量等，脚本读取后写入配件记录 |

#### 收货表（配件库存）

| 字段 | 类型 | 作用 |
|------|------|------|
| 关联整机记录 | 关联引用 → 辅助表格 | 标识配件属于哪条整机记录 |
| 配件标记 | 单选/文本 | L / R / C |
| 配件序号 | 数字 | 1=L, 2=R, 3=C，用于排序 |
| …其他字段… | — | 从整机记录继承 |

#### 操作面板（新建）

| 字段 | 类型 | 作用 |
|------|------|------|
| 名称 | 文本 | 固定值，如"配件拆分控制台" |
| 批量拆分 | 按钮 | 点击触发自动化 |

> 只建 1 条记录即可，按钮放在这条记录上。

## 自动化配置

```
触发：按钮被点击（操作面板.批量拆分）
  ↓
动作：运行脚本（JavaScript）
```

**无需任何其他动作**。所有逻辑都在脚本里完成。

## 脚本实现

### 完整脚本代码

将以下代码粘贴到飞书自动化「运行脚本」动作中：

```javascript
// ============================================================
// 配件拆分脚本 — 将整机收货记录拆分为 L/R/C 三条配件记录
// 运行环境：飞书多维表格自动化 → 运行脚本
// ============================================================

// ---------- 配置区（根据实际表名和字段名修改）----------
const CONFIG = {
  // 表名
  sourceTable: '辅助表格',           // 整机收货记录的来源表
  targetTable: '收货表',             // 配件记录的目标表

  // 来源表字段名
  sourceKey: '整机编号',              // 整机记录的唯一标识（文本/自动编号）
  autoGenerate: '自动生成',           // 复选框：用户勾选 = 待拆分
  processed: '已拆分',                // 复选框：脚本勾选 = 已处理

  // 目标表字段名
  linkField: '关联整机记录',          // 关联引用，指向来源表
  partMark: '配件标记',               // 单选/文本：L / R / C
  partSeq: '配件序号',                // 数字：1 / 2 / 3

  // 要从来源表复制到目标表的字段映射
  // key = 来源表字段名, value = 目标表字段名
  fieldMapping: {
    '型号': '型号',
    '颜色': '颜色',
    '成色': '成色',
    // 按实际情况增删
  }
};

// ---------- 主逻辑 ----------
async function main() {
  console.log('=== 配件拆分脚本开始 ===');

  // 1. 获取表对象
  const srcTable = await bitable.getTable(CONFIG.sourceTable);
  const tgtTable = await bitable.getTable(CONFIG.targetTable);

  // 2. 查询所有「自动生成=是 且 已拆分≠是」的整机记录
  const { records } = await srcTable.getRecords({
    filter: {
      [CONFIG.autoGenerate]: { operator: 'is', value: true },
      [CONFIG.processed]:    { operator: 'isNot', value: true }
    },
    pageSize: 200  // 一次最多处理 200 条
  });

  if (records.length === 0) {
    console.log('没有待拆分的整机记录');
    return { success: true, count: 0, message: '没有待拆分的记录' };
  }

  console.log(`找到 ${records.length} 条待拆分记录`);

  // 3. 按整机编号排序，确保处理顺序可预期
  records.sort((a, b) => {
    const idA = a.fields[CONFIG.sourceKey] || '';
    const idB = b.fields[CONFIG.sourceKey] || '';
    return String(idA).localeCompare(String(idB));
  });

  let successCount = 0;
  const errors = [];

  // 4. 逐条处理 —— for + await 保证串行顺序
  for (const record of records) {
    try {
      console.log(`处理整机：${record.fields[CONFIG.sourceKey]}`);

      // 4a. 准备从来源表复制的通用字段
      const sharedFields = {};
      for (const [srcField, tgtField] of Object.entries(CONFIG.fieldMapping)) {
        if (record.fields[srcField] !== undefined) {
          sharedFields[tgtField] = record.fields[srcField];
        }
      }

      // 4b. 依次生成 L → R → C（用 await 保证写入顺序）
      const parts = [
        { mark: 'L', seq: 1 },
        { mark: 'R', seq: 2 },
        { mark: 'C', seq: 3 }
      ];

      for (const part of parts) {
        await tgtTable.addRecord({
          fields: {
            [CONFIG.linkField]: record.id,       // 关联引用用 record ID
            [CONFIG.partMark]: part.mark,
            [CONFIG.partSeq]: part.seq,
            ...sharedFields
          }
        });
        console.log(`  -> 已创建 ${part.mark} (序号 ${part.seq})`);
      }

      // 4c. 标记来源记录为已处理
      await srcTable.updateRecord(record.id, {
        fields: {
          [CONFIG.processed]: true
        }
      });

      successCount++;
      console.log(`  -> 整机处理完成 ✓`);

    } catch (err) {
      console.error(`处理失败：${record.fields[CONFIG.sourceKey]}`, err.message);
      errors.push({
        record: record.fields[CONFIG.sourceKey],
        error: err.message
      });
    }
  }

  // 5. 返回执行摘要
  const summary = {
    success: errors.length === 0,
    count: successCount,
    total: records.length,
    errors: errors.length > 0 ? errors : undefined,
    message: `成功拆分 ${successCount} / ${records.length} 条整机记录`
  };
  console.log(`=== 脚本结束：${summary.message} ===`);
  return summary;
}

// 飞书自动化脚本入口
module.exports = main;
```

### 脚本关键点

| 要点 | 说明 |
|------|------|
| **`for...of` + `await`** | 保证顺序的核心。循环内的 `await tgtTable.addRecord()` 等待写入完成再继续下一步，L→R→C 逐个写入 |
| **`records.sort()`** | 多条整机记录按编号排序处理，先来的先拆分 |
| **`processed` 标记** | 防止同一条整机记录被重复拆分 |
| **`pageSize: 200`** | 单次最多 200 条。超出时多点击几次按钮即可 |
| **`fieldMapping`** | 集中配置字段映射，新增/删减复制字段只需改这里 |
| **错误处理** | 某条记录出错不阻断后续，记录错误信息继续处理 |

## 操作流程

1. 在辅助表格录入整机收货信息
2. 勾选该行的「自动生成」复选框（可拖拽批量勾选）
3. 切到「操作面板」，点击「一键拆分配件」按钮
4. 等待几秒（100 条约 10-15 秒），脚本完成
5. 切回收货表，查看生成的配件记录

> 超过 200 条时分多次点击按钮。已处理的记录会自动跳过。

## 视图配置建议

在收货表中创建以下视图以保持数据可读：

| 视图名 | 类型 | 分组 | 排序 | 用途 |
|--------|------|------|------|------|
| 配件清单（按整机） | 表格 | 关联整机记录 | 配件序号 升序 | 按整机展开查看 L/R/C 配件明细 |
| 配件库存总览 | 看板 | 配件标记 | — | 按 L/R/C 统计库存分布 |

## 验证方式

1. 在辅助表格新建 5 条测试记录，勾选「自动生成」
2. 点击操作面板的「一键拆分配件」
3. 检查收货表：应有 15 条记录（5 × 3），每条整机对应 L/R/C 且序号 1/2/3
4. 切换到「配件清单（按整机）」视图，确认按整机分组后 L→R→C 排列正确
5. 再次点击按钮，确认不会重复生成
6. 取消一条记录的「已拆分」并重新勾选「自动生成」，再次点击按钮，确认只处理了新增的 1 条
