你已经用飞书多维表格搭了一套仓库管理（主表0517，27 张子表），同时手里还有一份 Excel「商品进库表」想导进去。但两套结构不完全一样，不知道是合并还是新建——**这就是典型的"Excel 搬家的迷失期"**。

一句话诊断：

### 现有系统的"聪明设计"（应该保留）

看采购收货表的字段结构，这些设计很到位：

```
到货编号(DH自动编号) → 物流单号 → 商品编码 → 发货数量 vs 到货数量 → 自动判断差异
→ 测试坏品数 → 可入库数量(公式) → 收货人 → 采购短号
```

- ✅ 自动编号 DH00001-... 
- ✅ 到货数量 vs 发货数量自动对比
- ✅ 坏品检测提醒（公式：如果坏品数为空则报错）
- ✅ 可入库数量自动计算
- ✅ 商品编码作为主键（型号-颜色-成色-配件）

这套逻辑是 **CGD→DH→QC→RKD** 三层对账体系（见方案02）的核心实现，**不应该推翻**。

### 现有系统的"弯路"（建议清理）

1. **9 张空表** → 占位但没用，增加认知负担
2. **总表试图做"万能仪表盘"** → 字段多但数据稀疏，飞书的看板+仪表盘能做得更好
3. **多个"生成XX"表** → 说明你想过自动化但没落地，这些等飞书原生自动化机器人跑顺再加
4. **辅助填表×2 + 采购收货表2** → 说明原有的采购收货表填起来有痛点，才搞辅助表
5. **质检出入库登记是空的** → 质检流程（方案03）还没跑起来

## 第二步：商品进库表的"真面目"

### 这张表在做什么

商品进库表是**二手 TWS 耳机收购的采购记录**，一行 = 一次采购单品。

```text
典型一行：
freeclip | 黑*5白*1 | 6 | 570 | 3420 | (空物流) | (空短号) | (空时间) ...
```

### 和主表0517 采购收货表的字段映射

| 商品进库表 | → | 主表0517 采购收货表 | 差异判断 |
|-----------|------|-------------------|---------|
| 采购的耳机型号 | → | 商品型号 | **一致**，但需拆分为商品基础信息 |
| 颜色 | → | 颜色 | **一致**，但颜色里混了数量（"黑*5白*1"） |
| 成色 | → | 成色 | **一致** |
| 采购数量 | → | 发货数量 | 语义一致（都是"买了多少"） |
| 采购单价 | → | 商品单价 | **一致** |
| 采购总价 | → | 采购总价 | **一致** |
| 物流单号 | → | 物流单号 | **一致** |
| 采购短号 | → | 采购短号 | **一致** |
| 采购时间 | → | 到货日期/发货日期 | **接近**，但采购时间≠到货时间 |
| 采购店铺/供应商 | → | 供应商名称 | **一致** |
| 采购账号 | → | （无） | 采购收货表缺此字段 |
| 签收日期 | → | 到货日期 | **一致** |
| 测试人员 | → | （无） | 采购收货表有"测试坏品数"但没有测试人 |
| 测试完成日期 | → | （无） | 同上 |
| 备注 | → | 备注（原Excel无此独立列？） | |

### 数据质量问题

商品进库表有 3 个需要**清洗**的问题：

**问题 1：颜色字段混入数量和组件信息**
```
"黑*5白*1"       → 应该拆成：黑色×5 + 白色×1（但一个商品编码对应一行，不应该混）
"紫仓+黑左+黑右"  → 这是三个不同 SKU（仓、左耳、右耳）硬塞在一行
"白色：左*1右*1"  → 同理，需要拆行
```
这意味着你需要先把一行拆成多行（按组件），每条是唯一的商品编码。

**问题 2：负数量调整行**
```
行4：采购数量=-1，采购总价=-30
```
这是 Excel 时代的纠错方式——用负行冲销。在飞书里应该直接修改原记录或用"退货/冲销"独立记录。

**问题 3：采购短号是批次概念**
```
15928 → freebudspro3蓝色二手×2 + (一行的瑕疵扣减)
15929 → freebuds6i×4
```
短号 = 一个采购批次，多条商品行共享同一个短号。这和主表0517 的 DH 编号是不同层级：**DH 是到货单号，短号是采购批次号**。

## 第三步：到底要不要新建表？——三条路

### 路径 A：直接导入，新建独立子表 ❌ 不推荐

把商品进库表当作第 28 张表丢进飞书。最快，但：
- 和现有采购收货表数据**割裂**，以后查"今天到了哪些货"要翻两张表
- 字段不统一（有 采购账号、颜色格式不同），将来合并更痛苦
- 现在省事 = 以后加倍还

### 路径 B：全部合并到采购收货表 ⚠️ 可行但有代价

把商品进库表数据清洗后导入现有的采购收货表：
- 需要先解决颜色/组件拆分问题（一行拆多行）
- 采购收货表缺"采购账号""测试人员""测试完成日期"字段
- 二手商品和新品采购混在一起，筛选靠成色字段

### 路径 C：采购收货表做"数据底座" + 按业务场景分"视图" ✅ 推荐

**不新建表，而是让现有表更聪明地工作。**

核心思路：
1. **采购收货表**加 3 个字段（采购账号、测试人员、测试完成日期）
2. 商品进库表数据清洗后导入采购收货表
3. 用飞书**视图**区分"新品采购"和"二手收购"（按成色/货源筛选）
4. 商品的组件维度（仓/左耳/右耳）在商品信息表中正确建模
5. 同时**做减法**——清理 9 张空表，合并辅助表

## 🏗️ 第四步：具体执行方案

### 4.1 数据清洗：商品进库表 → 采购收货表

**第 1 步：拆分混在一起的组件行**

一个典型的商品进库表行：
```
freebudsse2 | 紫仓+黑左+黑右 | 2 | 55 | 110
```
实际上这是 **3 个 SKU**：
- freebudsse2-紫-C（仓）×1
- freebudsse2-黑-L（左耳）×1
- freebudsse2-黑-R（右耳）×1

清洗后的飞书导入格式：

| 商品型号 | 颜色 | 成色 | 配件 | 商品编码 | 发货数量 | 单价 | 供应商 | 采购短号 |
|---------|------|------|------|---------|---------|------|--------|---------|
| freebudsse2 | 紫 | 二手 | C | freebudsse2-紫-09-C | 1 | 55 | 婷婷 | 15929 |
| freebudsse2 | 黑 | 二手 | L | freebudsse2-黑-09-L | 1 | 55 | 婷婷 | 15929 |
| freebudsse2 | 黑 | 二手 | R | freebudsse2-黑-09-R | 1 | 55 | 婷婷 | 15929 |

**第 2 步：处理负数量行**

不导入负数量行。改为：
- 去原行修改数量（如果同一批次）
- 或新建一条"冲销"记录，备注注明"冲销[原采购短号]"

**第 3 步：统一商品编码**

商品编码格式对齐主表0517 现有规则：
```
{型号}-{颜色简称}-{成色代码}-{配件}
freebuds6i-b-09-C
```

### 4.2 采购收货表追加字段（3 个）

| 新增字段 | 类型 | 来源 | 说明 |
|---------|------|------|------|
| 采购账号 | 文本 | 商品进库表.采购账号 | 哪个账号付的款 |
| 测试人员 | 人员 | 商品进库表.测试人员 | 谁做的质检 |
| 测试完成日期 | 日期 | 商品进库表.测试完成日期 | 质检什么时候完成的 |

> 这 3 个字段也适用于新品采购的 QC 流程，不是只给二手用的。

### 4.3 商品信息表同步更新

导入前，先把商品进库表中出现的新型号/新 SKU 补到商品信息表。

从数据中提取到的**未建档 SKU**（需要人工确认是否已在飞书中）：
- freebuds6i, freebudsse3, freebudsse4, freebuds5, freebuds4e, freebuds4, freebudsse2
- freebuds5i, freebudspro2, freebudspro4
- 以及各型号的 仓/耳 组件变体

### 4.4 飞书表减肥计划

| 操作 | 表 | 理由 |
|------|------|------|
| 🗑️ 删除 | 采购表 | 空表，采购数据已在采购收货表 |
| 🗑️ 删除 | 生成采购单 | 空表，自动化未上线 |
| 🗑️ 删除 | 生成质检单 | 空表，自动化未上线 |
| 🗑️ 删除 | 生成入库表 | 空表，自动化未上线 |
| 🗑️ 删除 | 质检出入库登记 | 空表，如方案03所述质检记录应是有数据后独立表 |
| 🗑️ 删除 | 销售数据 | 空表，将来销售出库建独立表 |
| 🔀 合并 | 辅助填表_采购收货(芳) + 辅助填表_采购收货2(芳) → 删除 | 用飞书"表单视图"替代辅助填表 |
| 🔀 合并 | 采购收货表2 → 合并到采购收货表 | 同一张表的两个版本应统一 |
| 🔀 合并 | 生成采购单2 → 删除 | 同上 |
| ⏸️ 保留 | 自动建单、建快递单 | 可能被自动化引用，先不动 |
| ✅ 保留 | 兼职工作日志、兼职工资单 | 独立业务，不影响仓储 |

**结果：27 张 → 约 12~14 张有效表，干净清爽。**

### 4.5 用视图替代"辅助填表"

你现有的"辅助填表_采购收货(芳)"是为特定人（芳）定制的简化输入界面。

飞书原生功能直接能做：
- 为采购收货表创建**表单视图** → 只暴露必填字段（商品编码 + 发货数量 + 物流单号）
- 可以配置**多个表单视图**给不同角色："收货员表单"（3个字段）vs "QC检测表单"（加坏品数字段）
- 这比你建辅助子表优雅得多

### 4.6 采购短号 vs DH 编号 vs 物流单号

当前存在三个"编号"概念，关系如下：

```
采购短号 (15928)  ──1:N──→  DH编号 (DH00001)  ──1:1──→  物流单号 (SFxxx)
   │                              │
   │                        一个DH=一笔到货
   一个短号=一个采购批次
   可能分次到货
```

建议：
- **采购短号**保留在采购收货表中作为分组字段
- **DH 编号**是飞书自动生成的唯一主键
- 在采购收货表看板视图中按"采购短号"分组，就能看到每个批次的到货进度

## 关键取舍

| 决策 | 选了什么 | 为什么不选另一个 |
|------|---------|----------------|
| 商品进库表不建独立子表 | 合并到采购收货表 | 独立子表造成数据割裂，将来查库存要对两张表 |
| 保留采购收货表现有 DH 编号体系 | DH 继续做主键 | 自动编号+差异检测公式已跑通，推翻成本高 |
| 二手和新品用同一张表+视图区分 | 视图筛选 | 物理流程相同（到货→清点→QC→入库），建两张表是过度设计 |
| 本次暂不动自动化 | 先清数据再谈自动化 | 空表"生成XX"的存在说明自动化条件不成熟 |
