# 04 补充 — 视图配置实操：采购收货表 4 视图 + 质检纸单替代

> 产出日期：2026-05-17 | 状态：实操指南 | 基于 04 方案路径 C 的具体落地

---

## 背景

04 号方案选择了**路径 C**：采购收货表做"数据底座" + 按业务场景分"视图"，不新建表。

但在第一次落地时，只建了 3 个通用视图（到货登记、QC待检测、全部记录），**漏掉了最核心的「质检工作单」视图**——即按物流单号分组、供质检员逐 SKU 标记良品/坏品的工作视图。

本补充方案完整定义 4 个视图的配置细节，并给出用飞书移动端替代纸质质检单的操作流程。

## 实际业务流程还原

根据 `_business/质检表格.xlsx` 中的「采购单明细导出」和「质检单模板」，当前纸质流程为：

```
ERP导出采购单明细 → 仓库管理员复制到质检单模板
→ 打印纸质质检单（含：采购短号/货源/测试员 + 每个SKU的规格别名+数量）
→ 交给质检员 → 质检员逐SKU标记良品/坏品（充电仓/左耳/右耳）
→ 返回纸质单 → 仓库管理员登记到商品进库表
```

一个质检单模板的关键结构：

```
采购短号:______          货源:______
测试员:______            清洁员:______
开单日期:______          完成日期:______

         良品              坏品
充电仓:  ___              充电仓: ___
左耳:    ___              左耳:   ___
右耳:    ___              右耳:   ___

规格别名(SKU)              采购数量    单价    总价
rmbuds6vital-1-09-C-kz    3220
rmbuds6vital-1-09-R-kz    3220
rmbuds6vital-1-09-L-kz    3220
```

**核心洞察**：质检单的本质是按「物流单号」分组的 SKU 清单，而不是按「测试人员」分组。一个物流单号 = 一个包裹 = 一张质检工作单。

## 🏗️ 飞书端配置：4 个视图

以下 4 个视图全部基于同一张 **采购收货表**，不新建子表。

### 视图 1：📦 到货登记

| 配置项 | 值 |
|--------|-----|
| 视图类型 | 表格视图 |
| 筛选条件 | `测试完成日期` = 空 |
| 排序 | `到货日期` 降序 |
| 隐藏字段 | 测试人员、测试完成日期、测试坏品数、可入库数量 |
| 用途 | 仓库管理员快速录入到货信息，字段少、干扰少 |
| 使用者 | 仓库管理员 |

### 视图 2：📋 质检工作单 ⭐ 核心新增

| 配置项 | 值 |
|--------|-----|
| 视图类型 | 表格视图 |
| **分组依据** | `物流单号` |
| 筛选条件 | `测试完成日期` = 空 |
| 排序 | `到货日期` 升序 |
| 显示字段 | 商品编码、配件、到货数量、测试坏品数、可入库数量、测试人员、测试完成日期 |
| 用途 | 按包裹出单，每个物流单号折叠为一个组，展开即该包裹的全部待检 SKU |
| 使用者 | 质检员（手机飞书打开，直接对着货物逐行填） |

> **这是替代纸质质检单的关键视图。** 质检员在手机上打开飞书 → 切换到本视图 → 找到对应物流单号分组 → 逐行检查 → 填 `测试坏品数` → 填完一个 SKU 后公式自动算 `可入库数量` → 全组填完填 `测试完成日期` → 该组自动从视图中消失。

### 视图 3：🔬 QC 待办看板

| 配置项 | 值 |
|--------|-----|
| 视图类型 | 看板视图 |
| 分组依据 | `测试人员` |
| 筛选条件 | `测试完成日期` = 空 |
| 卡片显示 | 商品编码、到货数量、物流单号 |
| 用途 | 管理者看谁手上还有未完成的检测任务 |
| 使用者 | 管理者 |

### 视图 4：✅ 全部记录

| 配置项 | 值 |
|--------|-----|
| 视图类型 | 表格视图 |
| 筛选 | 无 |
| 排序 | `到货日期` 降序 |
| 显示 | 所有字段 |
| 用途 | 完整数据查阅、导出、修正 |
| 使用者 | 管理者/仓库管理员 |

---

## 四个视图的关系

```
仓库管理员收到货
       ↓
  [📦 到货登记] ← 快速录入，3~5 个字段
       ↓
  数据自动出现在 ↓
       ↓
  [📋 质检工作单] ← 质检员打开，按物流单号分组，逐 SKU 检测
       ↓
  质检员填完一个 SKU 的坏品数 → [📋 质检工作单] 该行仍可见（等填日期）
  质检员填完整个物流单号下所有 SKU → 填 测试完成日期 → 该组消失
       ↓
  [🔬 QC 待办看板] ← 管理者看全局，谁还有多少没检完
       ↓
  [✅ 全部记录] ← 历史查询、导出
```

## 飞书移动端操作流程（替代纸质单）

### 仓库管理员端（电脑）

1. 收到快递 → 打开飞书多维表格
2. 切换到 `📦 到货登记` 视图
3. 录入：商品编码、发货数量、物流单号、到货日期、采购短号
4. 系统自动生成 DH 编号

### 质检员端（手机飞书）

1. 打开飞书 App → 进入多维表格
2. 切换到 `📋 质检工作单` 视图
3. 找到对应物流单号分组（例如 SF0216541329217）
4. 展开分组，看到该包裹下所有 SKU：
   ```
   SF0216541329217
   ├── rmbuds6vital-1-09-C-kz  充电仓  数量：3220  坏品：___
   ├── rmbuds6vital-1-09-R-kz  右耳    数量：3220  坏品：___
   └── rmbuds6vital-1-09-L-kz  左耳    数量：3220  坏品：___
   ```
5. 逐行检查实物，填入 `测试坏品数`
6. 全部查完，填 `测试完成日期`
7. 该分组自动从视图中消失 → 检测完成

### 管理者端（电脑/手机）

1. 切换到 `🔬 QC 待办看板` 视图
2. 看到按测试人员分组的卡片，一眼看出谁手上堆积了多少待检
3. 发现某人的待检卡超过 3 天未动，立刻跟进

---

## 关键决策

| 决策 | 理由 |
|------|------|
| 质检工作单视图按「物流单号」分组，不是按「测试人员」 | 一个物流单号 = 一个包裹 = 一张质检单，质检员逐 SKU 检查的物理单位是包裹 |
| 质检工作单用「表格视图」而非「看板视图」 | 需要在同一个物流单号下看到全部 SKU 行，看板的卡片模式不适合逐行编辑 |
| 质检员直接用手机飞书填，不打印纸质单 | 消除「打印→手写→回来登记」的二次录入，数据实时回表 |
| 4 个视图共享一张表 | 不是建 4 张表。视图 = 同一份数据的不同"眼镜" |

---

## 执行后效果

- **纸质质检单** → 被飞书 `📋 质检工作单` 视图替代
- **仓库管理员登记** → 收货时录入一次，后续数据自动流转
- **质检员二次录入** → 消除，质检结果直接填在原数据行上
- **管理者追问进度** → 打开看板，实时可见
