# 06-补充 — 配件拆分：无脚本按钮方案

> 产出日期：2026-05-22 | 状态：v1 初稿
> 对应脚本方案见 `_plans/06-配件拆分脚本方案.md`

## 背景

用户在「辅助表格」中输入一条整机收货记录，通过飞书自动化在「收货表」自动生成 3 条配件记录（L 左耳机 / R 右耳机 / C 充电仓）。当用户像 Excel 那样拖拽填充「自动生成」字段时，飞书自动化并发执行，导致生成顺序错乱。

**问题本质**：飞书原生自动化的触发是异步并发的。N 条记录同时触发 = N 个自动化实例并发运行，彼此不等待。

**本方案定位**：纯飞书原生功能，零代码（不写脚本）。适合不想写脚本或对脚本不熟悉的场景。

## 方案概要

两层修复，双管齐下：

| 层次 | 做什么 | 效果 |
|------|--------|------|
| 第一层 | 收货表加排序字段，创建排序视图 | 无论生成顺序多乱，视图始终显示正确顺序 |
| 第二层 | 触发方式从复选框改为按钮 | 逐行点击，天然串行，从根本上避免并发 |

## 第一层：让乱序不可见

### 表结构调整

#### 辅助表格（整机收货）— 新增字段

| 字段 | 类型 | 作用 |
|------|------|------|
| 拆分配件 | 按钮 | 点击触发自动化，生成当前行的 L/R/C 配件记录 |

> 按钮字段是飞书多维表格原生字段类型。每个按钮独立存在，点哪行就处理哪行。

#### 收货表（配件库存）— 新增字段

| 字段 | 类型 | 作用 |
|------|------|------|
| 关联整机记录 | 关联引用 → 辅助表格 | 标识配件属于哪条整机记录 |
| 配件标记 | 单选：L / R / C | 区分左右耳和充电仓 |
| 配件序号 | 数字 | 1=L, 2=R, 3=C，用于排序 |

### 自动化配置

```
触发：按钮被点击（辅助表格.拆分配件 按钮）
  ↓
动作1：新增记录（收货表）
  关联整机记录 = 当前记录
  配件标记 = "L"
  配件序号 = 1
  型号 = 当前记录.型号
  颜色 = 当前记录.颜色
  ...其他从整机继承的字段
  ↓
动作2：新增记录（收货表）
  关联整机记录 = 当前记录
  配件标记 = "R"
  配件序号 = 2
  ...（同上）
  ↓
动作3：新增记录（收货表）
  关联整机记录 = 当前记录
  配件标记 = "C"
  配件序号 = 3
  ...（同上）
```

**关键**：3 个「新增记录」动作在**同一条自动化内按先后顺序执行**。飞书保证同一条自动化内部的动作是顺序执行的（动作 2 等动作 1 完成才开始）。

### 操作流程

1. 在辅助表格录入整机收货信息
2. 点击该行的「拆分配件」按钮
3. 等待 1-2 秒，3 条配件记录出现在收货表中
4. 处理下一行：点击下一行的「拆分配件」按钮

> 速度参考：每条整机约 2-3 秒，30 条约 1 分钟。

### 视图配置

在收货表中创建排序视图，让数据始终按正确顺序显示：

| 视图名 | 类型 | 分组 | 排序 | 用途 |
|--------|------|------|------|------|
| 配件清单（按整机） | 表格 | 关联整机记录 | 配件序号 升序 | 按整机展开，L→R→C 依次排列 |
| 配件库存总览 | 看板 | 配件标记 | — | 按 L/R/C 分类统计 |

### 效率考量

| 场景 | 适用性 |
|------|--------|
| 每天 < 30 条整机 | 完全够用，逐行点击约 1 分钟 |
| 每天 30-100 条 | 可行但稍慢，可边录入边点击 |
| 每天 > 100 条 | 建议用脚本方案（`06-配件拆分脚本方案.md`） |

## 第二层：为什么按钮能解决根本问题

对比两种触发方式：

```
复选框拖拽填充（旧方案）：
  行1 自动生成=✓  ──→ 自动化实例A ──┐
  行2 自动生成=✓  ──→ 自动化实例B ──┤ N 个实例并发运行
  行3 自动生成=✓  ──→ 自动化实例C ──┘ 写入顺序无法预测

按钮逐行点击（新方案）：
  点击行1按钮 ──→ 自动化实例A（写 L₁→R₁→C₁）──→ 完成
  点击行2按钮 ──→ 自动化实例B（写 L₂→R₂→C₂）──→ 完成
  点击行3按钮 ──→ 自动化实例C（写 L₃→R₃→C₃）──→ 完成
  每个实例完整执行后才开始下一个，不会交叉
```

**按钮是逐行点击的物理动作**，用户什么时候点击下一行，完全由用户控制节奏。

### 边界情况：快速连续点击 5 个按钮会怎样？

**先澄清一点**：按钮字段的拖拽填充 = 仅复制按钮 UI 到其他单元格，**不会触发自动化**。这和 Excel 拖公式触发了重算完全不同。

但如果你**手动快速连点 5 行按钮**（比如 1 秒内点完），确实可能出现轻微交叉：

```
时间轴 →
0.0s: 点击行1按钮 → 实例A开始
0.2s: 点击行2按钮 → 实例B开始（A还在写R₁）
0.4s: 点击行3按钮 → 实例C开始（A和B都还在执行）
...

收货表中的实际写入顺序可能是：
  A写L₁ → B写L₂ → A写R₁ → C写L₃ → B写R₂ → A写C₁ → ...
```

**两个关键保证**：

| 保证 | 说明 |
|------|------|
| ✅ 单条记录内部不乱 | 实例 A 的 L₁→R₁→C₁ **永远按序执行**，飞书保证同一自动化内的动作是顺序的 |
| ⚠️ 记录之间可能穿插 | 不同实例之间是并发的，A 和 B 的写入可能交替 |

**如何应对**：

- **日常正常节奏点击**（每次间隔 1-2 秒）：前一个实例基本执行完了，几乎不会穿插
- **极快速连点**（0.2 秒间隔）：可能穿插，但第一层的 **`配件序号` + 排序视图** 让你根本看不出来乱序
- **需要绝对顺序保证**：用脚本方案（`06-配件拆分脚本方案.md`），所有记录在一个 `for` 循环里串行处理

**结论**：按钮方案在正常使用下完全够用。拖拽填充按钮不触发、正常节奏点击不穿插、万一穿插了排序视图也掩蔽了。追求 100% 确定性就用脚本。

## 验证方式

1. 在辅助表格新建 3 条测试整机记录
2. 逐行点击每条记录的「拆分配件」按钮
3. 检查收货表：
   - 是否有 9 条记录（3 × 3）
   - 每条整机对应的 L/R/C 配件序号是否为 1/2/3
4. 快速连续点击 3 个按钮（模拟最快手速），验证不会交叉
5. 切到「配件清单（按整机）」视图，确认按整机展开后 L→R→C 排列正确
6. 确认某行按钮不会重复生成（如果需要防重复，可在自动化中加判断条件）

## 与脚本方案的对比

| 维度 | 无脚本按钮方案（本方案） | 脚本方案（06 主方案） |
|------|--------------------------|------------------------|
| 实现难度 | 低，纯配置 | 中，需写 JS |
| 操作方式 | 逐行点击按钮 | 批量勾选 + 一键执行 |
| 单次处理量 | 1 条/次 | 最多 200 条/次 |
| 防重复 | 需额外加判断条件 | 脚本内置 `已拆分` 标记 |
| 出错处理 | 飞书默认行为 | 脚本内 try-catch + 摘要 |
| 维护成本 | 低 | 中（字段名改了要改代码） |
| 适合场景 | 日处理量 < 30 条 | 日处理量 > 50 条 |

**建议**：先上无脚本方案跑通流程，确认表结构和字段映射都稳定后，如果量大了再切脚本方案。
