# 05 — 不良品采退结算方案：区分退货/补差，按物流单号自动结算

> 产出日期：2026-05-17 | 状态：待执行 | 基于 04-补充 方案的字段级增强

---

## 背景

当前 `采购收货表` 只有一个 `测试坏品数` 数字字段，不区分不良品的两种处理模式：

- **Mode 1（全额退货退款）**：坏品退回供应商 → 按原采购单价全额退款冲减 → 不进库存
- **Mode 2（补差留货）**：坏品留作零件/维修 → 供应商固定补偿 30 元/件 → 仍进库存（当零件）

这导致无法自动核算每个 **物流单号（结算批次）** 的实际应付金额。

**本次方案**：在采购收货表上增强字段，用公式自动计算行级实付金额，用分组视图实现"一键看批次结算"，遵循 Plan 04 Path C（一表多视图，不新建子表）。

---

📍 第一阶段：业务流程映射

```
仓库收货 → 📦到货登记 录入（仓管）
         → 数据自动流入 📋质检工作单
质检     → 手机打开 📋质检工作单，按物流单号找到包裹
         → 逐 SKU 检测：
           ├── 正常品 → 不填坏品
           ├── Mode 1 需退货 → 填「退货坏品数」
           └── Mode 2 补差留 → 填「补差坏品数」
         → 系统实时算出行级实付金额
         → 全组填完 → 填「测试完成日期」→ 该组从质检视图消失
结算     → 财务打开 💰结算总览视图
         → 按物流单号分组 → 展开看每行明细
         → 组尾部显示：采购总额 / 退货冲减 / 补差冲减 / 实付合计
         → 确认支付人 → 打款
对账     → 导出 💰结算总览 → Excel 透视物流单号
         → VLOOKUP 匹对旧系统（商品进库表）同物流单号汇总
         → 核心校验：新系统 SUM(实付金额) = 旧系统 SUM(全部行含负行)
```

核心变化：
- **坏品字段一拆二**：质检员区分"退货"和"补差留"，不再混为一谈
- **结算金额自动算**：行级实付金额 = 采购总价 - 退货冲减 - 补差冲减，无需手工算
- **一键出结算单**：切换到 💰结算总览视图即见每个物流单号的应付款

🏗️ 第二阶段：MVP 数据底座（核心配置）

## 1. 字段改造（采购收货表）

### 删除 1 个

| 字段 | 原因 |
|------|------|
| `测试坏品数`（原数字字段） | 替换为公式字段。当前所有行该字段为空，零数据丢失风险 |

### 新增 7 个

| # | 字段名 | 类型 | 公式 / 默认值 | 谁来填 | 说明 |
|---|--------|------|-------------|--------|------|
| 1 | `退货坏品数` | 数字 | — | 质检员 | Mode 1：退回供应商的坏品数量 |
| 2 | `补差坏品数` | 数字 | — | 质检员 | Mode 2：留作零件的坏品数量 |
| 3 | `补差单价` | 数字 | 默认值 **30** | 一般不动 | 每件补差金额，特殊供应商/品类可手动调整 |
| 4 | `退货冲减金额` | 公式 | `{退货坏品数} * {商品单价}` | 自动 | 全额退款 = 坏品数 × 采购价 |
| 5 | `补差冲减金额` | 公式 | `{补差坏品数} * {补差单价}` | 自动 | 补差扣减 = 坏品数 × 30 |
| 6 | `实付金额` | 公式 | `{采购总价} - {退货冲减金额} - {补差冲减金额}` | 自动 | **核心结算字段**：该行应付供应商净额 |
| 7 | `测试坏品数` | 公式 | `{退货坏品数} + {补差坏品数}` | 自动 | 替代原数字字段，总坏品数（兼容已有引用） |

### 修改 1 个

| 字段 | 旧公式 | 新公式 |
|------|--------|--------|
| `可入库数量` | `IF(测试坏品数="", "⚠️ 未检测——请填写坏品数", 到货数量 - 测试坏品数)` | `IF(AND({退货坏品数}="", {补差坏品数}=""), "⚠️ 未检测——请填写坏品数", {到货数量} - {退货坏品数})` |

> **关键区别**：Mode 2（补差留货）的坏品物理上仍在仓库（当零件），所以 **只减退货坏品数，不减补差坏品数**。这是与原 AI 设计的重要修正。

### 字段排列顺序

```
... 商品单价 → 到货数量 → 到货是否一致 → 采购总价 →
【新增三个数字字段】退货坏品数 → 补差坏品数 → 补差单价(默认30) →
【四个公式字段】测试坏品数 → 退货冲减金额 → 补差冲减金额 → 实付金额 →
【原有公式】可入库数量 → 到货日期 → 收货人 → ...
```

> 设计意图：质检员从左到右依次看到 → 商品 → 价格 → 填两个坏品数 → 自动计算结果。

## 2. 公式逻辑验证

| 场景 | 到货 | 单价 | 采购总价 | 退货 | 补差 | 退货冲减 | 补差冲减 | 实付 | 可入库 |
|------|------|------|---------|------|------|---------|---------|------|--------|
| 无坏品 | 10 | 100 | 1000 | 0 | 0 | 0 | 0 | 1000 | 10 |
| 纯退货 3 件 | 10 | 100 | 1000 | 3 | 0 | 300 | 0 | 700 | 7 |
| 纯补差 3 件 | 10 | 100 | 1000 | 0 | 3 | 0 | 90 | 910 | 10 |
| 混合（退2补3） | 10 | 100 | 1000 | 2 | 3 | 200 | 90 | 710 | 8 |

## 3. 旧系统兼容性说明

旧 Excel（商品进库表）用负数量行做冲减：`数量=-1, 单价=原价`（退货）或 `数量=-1, 单价=30`（补差）。新旧系统按物流单号汇总结算的数学结果等价：

| 新飞书 | 旧 Excel |
|--------|----------|
| `SUM(采购总价)` 按物流单号 | `SUM(正行金额)` 按物流单号 |
| `SUM(退货冲减金额)` 按物流单号 | `SUM(负行金额 where 单价=原采购价)` |
| `SUM(补差冲减金额)` 按物流单号 | `SUM(负行金额 where 单价=30)` |
| `SUM(实付金额)` 按物流单号 ← **核心校验** | `SUM(全部行金额含正负)` 按物流单号 |

## 条件格式化建议

| 触发条件 | 格式 | 含义 |
|---------|------|------|
| `退货坏品数` > 0 | 行背景浅红 | 该行有需退货的坏品 |
| `补差坏品数` > 0 | 行背景浅黄 | 该行有补差留货的坏品 |
| `实付金额` < `采购总价` | 实付金额列加粗蓝色 | 该行发生了财务冲减 |
| `退货坏品数 + 补差坏品数` > `到货数量` | 行背景深红 | 数据异常：坏品数不可能超到货数 |

🚀 第四阶段：未来演进路径

表格跑顺后可启用的增强：

1. **飞书自动化：结算完成通知付款人**
   - 触发器：`支付人` 字段被填写
   - 动作：飞书消息推送给支付人 → "物流单号 XXX 结算完成，应付 XXX 元，请打款"

2. **飞书自动化：坏品超限预警**
   - 触发器：某物流单号下退货率超过阈值（如 30%）
   - 动作：飞书消息推送给采购 → "物流单号 XXX 退货率 35%，请关注供应商质量"

3. **独立结算汇总表**（如果分组视图不够用）
   - 当批次结算需要持久化记录（如生成结算单号、记录付款日期）时，可新建「结算汇总表」
   - 每行 = 一个物流单号，通过查找引用汇总采购收货表的实付金额
   - 当前阶段暂不需要——分组视图已满足"看结算"需求

4. **审批流：大额退货审批**
   - 退货冲减金额超过阈值 → 自动发起退货审批 → 主管确认 → 通知采购执行退货

5. **供应商质量评分**
   - 基于历史退货率 + 补差率自动给供应商打分 → 采购下单时参考

## 边界情况与 FAQ

| 场景 | 预期行为 |
|------|---------|
| 只填退货、不填补差 | 补差视为 0，可入库 = 到货 - 退货 |
| 退货 + 补差 > 到货数量 | 数据异常（不可能坏品多于到货），条件格式红色告警 |
| 补差单价留空 | 补差冲减 = 0。务必确保字段有默认值 30 |
| 公式检测空值 | 优先用 `字段=""` 判断；如飞书不支持，改用 `ISBLANK(字段)` |
