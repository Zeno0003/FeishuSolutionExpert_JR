# 06 — 每日采购数据同步方案：Excel → 飞书采购收货表

> 产出日期：2026-05-21 | 状态：v2（修正数据粒度不匹配问题） | 基于 `今日采购表明细表.xlsx`

---

## 背景

你有一份来自第三方采购平台的"今日采购表明细表"，每天需要把新的采购记录同步到飞书的**采购收货表**中。核心字段：**物品编号、商品名称、合计**。

每天执行 1~N 次。

---

## 核心矛盾：数据粒度不同，不能直接导入

### 两张表在说不同的"语言"

```
采购平台 Excel（今日采购表明细表）
┌──────────────────────────────────────────────────────┐
│ 1 行 = 1 台整机（仓 + 左耳 + 右耳 打包卖）              │
│ 价格 = 整机总价（90 元）                               │
│ 只有 1 个 IMEI（整机识别码）                           │
│ 例：华为 FreeBuds 4E 陶瓷白 | C级 | 合计 90.00        │
└──────────────────────────────────────────────────────┘

飞书 采购收货表（已有数据）
┌──────────────────────────────────────────────────────┐
│ 1 行 = 1 个组件（仓 / 左耳 / 右耳 各占一行）            │
│ 编码 = freebuds4e-w-09-C / -L / -R                   │
│ 价格 = 单个组件价格                                   │
│ 例：freeclip-j-09-C → 仓 / freeclip-j-09-E → 双耳    │
└──────────────────────────────────────────────────────┘
```

### 直接导入的 3 个死结

| 问题 | 为什么没法直接导 |
|------|----------------|
| **1 行要变 3 行** | 平台 Excel 一行整机 → 飞书需要拆成仓/左/右 3 行。飞书导入不支持"一行拆多行" |
| **价格如何拆分** | 整机合计 90 元，仓值多少？左耳值多少？平台不告诉你，得你自己定规则（均分？按行情？） |
| **IMEI 对不上** | 平台给的是整机 IMEI，但飞书组件级需要每个仓/耳的独立识别码，收货时才能扫码确认 |

> **结论：不能也不应该把平台 Excel 直接导入采购收货表。**

---

## 正确方案：加一张"平台采购记录表"做缓冲层

### 整体架构

```
                         ┌──────────────────────────────┐
  Excel (整机) ──导入──→  │  🆕 平台采购记录表             │
                         │  1 行 = 1 台整机              │
                         │  字段与 Excel 列 1:1 对应     │
                         │  导入只需做列映射，无需拆分    │
                         │  每日导入耗时：2 分钟          │
                         └──────────┬───────────────────┘
                                    │ 1 : N（关联引用）
                                    │ 货物到仓后，手动拆分为组件
                                    ▼
                         ┌──────────────────────────────┐
                         │  采购收货表（已有，结构不动）   │
                         │  1 行 = 1 个组件（仓/左/右）   │
                         │  保持现有 DH 编号体系          │
                         │  新增 1 个关联字段即可         │
                         └──────────────────────────────┘
```

### 为什么这是正确的设计

| 对比维度 | 直接导入采购收货表 | 加缓冲表 |
|---------|-----------------|---------|
| 数据粒度 | 不匹配（整机→组件） | 各自保持正确粒度 |
| 导入速度 | 无法直接导 | 列 1:1 映射，2 分钟 |
| 现有数据 | 会被污染 | 完全不受影响 |
| 价格拆分 | Excel 里没这信息，硬拆会错 | 人到货时按实际行情填组件单价 |
| 组件 IMEI | 平台只给整机 IMEI | 收货时扫码录入每个组件的真实 IMEI |
| 重复导入防护 | — | 平台物品编号设唯一，自动拦截重复导入 |
| 追溯性 | — | 一条平台记录 → N 条收货记录，清晰可查 |

### 🏗️ 表 1：平台采购记录表（🆕 新建）

| 字段 | 类型 | 来源 Excel 列 | 说明 |
|------|------|-------------|------|
| **平台物品编号** | 文本（设为唯一） | 物品编号 | 防止同一条采购单重复导入 |
| 商品名称 | 文本 | 商品名称 | 整机型号，如"华为 FreeBuds 4E 陶瓷白" |
| IMEI/SN | 文本 | 物品imei | 平台提供的设备识别码 |
| 成色名称 | 文本 | 成色名称 | |
| 平台评级 | 单选（A/B/C/D） | 等级 | 平台给的质检等级 |
| 买家成交价 | 数字（元） | 买家成交价 | 商品本身价格 |
| 交易服务费 | 数字（元） | 交易服务费 | 平台手续费 |
| 红包卡券 | 数字（元） | 红包卡券 | 优惠抵扣 |
| **合计** | **公式** | — | `买家成交价 + 交易服务费 - 红包卡券`（自动算，无需导入） |
| 物品状态 | 单选 | 物品状态 | 已收货 / 待收货 / 已退款 |
| **关联收货记录** | **关联引用 → 采购收货表** | 手动 | 一条可关联多条（仓/左/右 3 条） |
| **拆分状态** | 单选 | 手动 | 待拆分 / 已拆分 |
| 采购日期 | 日期 | — | 默认创建日期 |
| 备注 | 多行文本 | — | 异常情况记录 |

> 导入时 Excel 列和表字段是 **1:1 映射**，合计由公式自动算，不需要拆分任何东西。

### 采购收货表只需加 1 个字段

| 新增字段 | 类型 | 说明 |
|---------|------|------|
| **来源平台单** | 关联引用 → 平台采购记录表 | 标记这个组件是从哪条平台采购记录拆出来的 |

> 现有字段（到货编号、商品编码、发货数量、到货数量、采购总价、收货人等）全部不变。

## 每日操作 SOP

### 第一部分：导入（每日 1~N 次，每次 2 分钟）

```
Step 1: 拿到最新 Excel 文件
Step 2: 飞书 → 平台采购记录表 → 右上角 "…" → 导入
Step 3: 选择 Excel，列映射（1:1 直接对上）
Step 4: 导入模式选 "追加" → 确认
Step 5: 完成 ✨
```

### 第二部分：拆分（货物到仓后执行，每条 1 分钟）

```
Step 1: 飞书 → 平台采购记录表 → 筛选「拆分状态 = 待拆分」
Step 2: 打开一条记录，确认货物实物已到
Step 3: 到采购收货表，新建 3 行：
        行 1：商品编码 = XXXX-颜色-成色-C（仓），填入仓的 IMEI、单价
        行 2：商品编码 = XXXX-颜色-成色-L（左耳），填入左耳 IMEI、单价
        行 3：商品编码 = XXXX-颜色-成色-R（右耳），填入右耳 IMEI、单价
        每行的「来源平台单」关联回平台采购记录
Step 4: 回到平台采购记录表，关联这 3 条收货记录，标记「已拆分」
```

## 后续升级（API 阶段）

当跑顺后，API 自动化可以分两步实现：

**第一步（简单）**：Excel → 平台采购记录表自动导入（Node.js 脚本读 Excel，调飞书 Open API 批量写记录）。这是纯新增，不影响任何现有数据。

**第二步（进阶）**：自动拆分。如果你定了明确的拆分规则（如 合计÷3 均分、按固定比例），脚本可以读完平台记录表后，自动在采购收货表创建 3 条组件记录并关联。但 IMEI 仍需人工扫码确认。

## 关键取舍

| 决策 | 选了 | 为什么不选另一个 |
|------|------|----------------|
| 建独立缓冲表 | ✅ | 直接导入采购收货表会导致数据粒度混乱，1 行整机混在几百条组件记录里无法区分 |
| 缓冲表在整机粒度 | ✅ | 和 Excel 源头保持一致，导入不用拆分 |
| 手动拆分而非自动 | ✅ | 组件价格、IMEI 都需要实物到场才能确定，自动化反而容易出错 |
| 采购收货表只加 1 个字段 | ✅ | 最小侵入，已有几百条数据完全不受影响 |
