# 2026-05-23 配件拆分调试与经验总结

## 背景
Phase 1 配件拆分功能已上线运行。用户首次运行拆分时发现 4 个问题，逐一排查解决。

## 问题与修复

### 1. 复选框过滤误匹配（已修复）
- **现象**：过滤 `已拆分 != true` 匹配了全部 167 条记录（实际只有 3 条未拆分）
- **根因**：飞书复选框未勾选 = 字段不存在，`!= true` 会把无字段的记录也匹配
- **修复**：改为 `NOT(CurrentValue.[已拆分])`
- **文件**：`server/src/commands/split.ts` → `getPendingRecords()`

### 2. 已拆分标记未回写（已修复）
- **现象**：拆分完成后，来源表记录未被勾选"已拆分"
- **根因**：前期调试改了调试脚本的原 filter，正式代码已正确，但用户前次运行时 filter 还有问题
- **状态**：filter 修复后自然解决

### 3. 取消功能（已实现）
- **实现**：`splitAccessories()` 增加 `shouldContinue` 回调 + SSE `req.on('close')`
- **文件**：`server/src/server.ts`, `server/src/commands/split.ts`

### 4. 供应商名称 MultiSelect 选项不一致（已知问题，暂不改）
- **现象**：记录 `[平台1-5-23-2 / freeclip2]` 写入时报 `1254302 Permission denied`
- **根因**：来源表 `供应商名称` 有选项"蔡雨诗"，目标表无此选项，API 校验失败
- **定位过程**：逐字段隔离测试（`_debug3.ts`），排除其他字段，确认 `供应商名称` 数组传入即失败、文本传入即成功
- **处置**：记录到 `_knowledge/字段选项不一致问题.md`，三个修复方向（降级文本/事前校验/源头对齐）待后续决策

## 架构认知

- 飞书 DuplexLink 字段写入后自动双向生效，来源表关联列会自动展示目标表记录
- 来源表与目标表同名字段的选项集可能不同步，是数据写入的主要风险点
- 测试数据无法通过 API 删除（缺 `base:record:delete` 权限），需在 UI 手动清理
